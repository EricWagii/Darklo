# 连续肌电编码输入设计

## 1. 目标

新增一个独立的“连续肌电编码”页面，将耳周可稳定采集的咬合肌电动作解释为类似摩斯电码的点、划和停顿，并实时解码为字符或文本。

该功能用于验证耳周单通道肌电在连续时序输入上的可用性。它不替代现有的采集训练和离散指令识别，也不得改变现有训练样本、识别历史或质量评分数据。

## 2. 产品边界

第一版包含：

1. 连接状态和静息状态检查。
2. 本次会话的短咬、长咬和静息校准。
3. 连续肌电动作检测及点、划、普通字符边界和强制分隔识别。
4. 支持宽松、可调的慢速输入节奏，允许受试者在字符之间思考和等待。
5. 实时波形、当前编码、解码文本和不确定状态显示。
6. 标准国际摩斯电码字母和数字对照表。
7. 暂停、继续、撤销上一字符、清空及导出本次会话。

第一版不包含：

1. 不训练 CNN、DTW 或新的语义分类模型。
2. 不写入指令、采集样本和现有识别历史数据库。
3. 不自动执行系统控制命令。
4. 不承诺默念语义识别，只验证有明显肌电活动的长短咬合编码。
5. 不在后台持续运行；仅在用户打开页面并明确开始后解码。

## 3. 页面和导航

新增受登录保护的路由 `/continuous-code`，首页提供明确入口“连续肌电编码”。页面沿用现有深色、克制的工作界面，不制作介绍型落地页。

页面从上到下包含：

1. 硬件与静息状态栏。
2. 校准区：依次采集静息、3 至 5 次短咬、3 至 5 次长咬。
3. 实时波形区：显示用于判定的单通道活动包络和动态阈值。
4. 实时解码区：使用 JetBrains Mono 等宽字体横向追加累计文本；文字末端光标连接动态横向磷光丝线和实心光点，光流必须真实运动和衰减，不能使用静态背景图代替。
5. 流式状态日志：在同一紧凑横栏内显示可连续追加的点划输入流、流分段状态、无效尾段和事件历史。点划输入流不按单个字符限制长度，默认定位到最新事件并允许横向回看；事件历史以小字号、低间距时间线按顺序显示点、划、候选字符边界、已确认字符和舍弃事件，不使用占据大量空间的大号符号卡片。
6. 节奏区：提供“标准/慢速/自定义”分段选择；节奏参数分别控制普通字符边界和强制分隔，不能把每个字符都绑定到数秒固定倒计时。
7. 对照表：常驻展示 A 至 Z、0 至 9 的字符、点划编码和便于辨认的分组。
8. 操作区：开始/暂停、强制分隔、撤销、清空、导出和返回首页。

按钮使用现有图标库；数值状态使用固定尺寸，避免实时数据导致布局跳动。

## 4. 模块边界

### 4.1 `continuous-emg-calibration`

输入为静息和短咬、长咬的单通道样本，输出会话级参数：

- 静息中心和噪声尺度；
- 动作开始阈值与结束阈值；
- 最短有效动作时长；
- 短咬和长咬的自适应分界时长；
- 字符内、普通字符边界和强制分隔阈值；
- 当前节奏模式及分段参数；
- 校准质量和失败原因。

短咬/长咬分界使用两组动作时长的稳健中位数中点，并要求两组之间存在最小分离度。分离不足时不允许开始正式解码。

### 4.2 `continuous-emg-detector`

将串口样本转为稳定的活动包络，采用双阈值迟滞、最短持续时间和去抖逻辑输出动作开始/结束事件。

检测器必须：

- 以当前静息噪声动态设阈值；
- 忽略过短尖峰；
- 将电极移动、饱和、长时间漂移和开场稳定过程标记为不可解码区间；
- 不因一次短暂低于阈值而把同一咬合拆成多次动作；
- 在信号恢复稳定前暂停产生点划符号。

### 4.3 `continuous-code-decoder`

纯流式解码器接收动作持续时间和动作之间的停顿时间：

- 短动作输出点，长动作输出划；
- 每个事件同时记录动作时长、结束时间和下一动作到来前的静息时长；
- 静息时长被归一化为字符内间隔、候选字符边界或强制分隔，不把一个固定长倒计时作为正常字符确认机制；
- 熟练用户通过短但可辨识的字符间隔连续输入，解码器应在不中断采集的情况下持续输出多个字符；
- 不熟练用户可通过较长静息触发强制分隔。强制分隔只处理尚未稳定提交的尾部，不清除或重写前面已经确认的字符；
- 强制分隔前若尾部包含多个可稳定识别的字符，则提交全部稳定字符；最后一个不完整、非法或低置信度片段被标记并舍弃；
- 强制分隔后到来的第一个点或划自动开始新的字符段；
- 不确定动作不猜测，保留原始事件并在事件历史中标记。

编码表使用标准国际摩斯字母和数字映射。解码器为纯函数模块，不依赖 React、IndexedDB 或串口实现，以便独立测试。

摩斯字符集合不是前缀无歧义编码。完全没有字符边界的纯点划串可能存在多种合法拆分，因此系统不得声称能够百分之百恢复无停顿连续输入。第一版通过“时序证据 + 候选路径 + 稳定前缀”兼顾效率和可靠性：

- 根据相邻动作之间的停顿为每个潜在字符边界计算时序得分；
- 使用动态规划保留有限数量的合法摩斯拆分候选，不使用语言模型强行猜测任意文本；
- 当高分候选共享相同字符前缀时，立即提交该稳定前缀，保留仍有分歧的尾部；
- 普通字符间隔阈值应短且可随本次会话节奏缓慢适应，使熟练用户无需等待数秒；
- 强制分隔阈值独立设置，仅用于结束模糊尾段或帮助不熟练用户恢复；
- 标准、慢速和自定义节奏只改变间隔分类参数，不改变短咬/长咬分界；
- 用户仍可撤销最近确认字符，但长静息本身只舍弃非法或不完整尾段，不回退合法稳定前缀。

页面上的点划输入流使用紧凑 JetBrains Mono 字符串显示，覆盖本次会话已接收的连续点划，而不是只预留单个字符的固定六位。已确认字符边界以细分隔标记呈现，候选边界使用更弱的视觉标记，未确认尾段保持高亮。输入流保持单行固定高度，默认自动跟随最新事件，并支持横向滚动回看；长输入不缩小字体、不换行，也不挤压相邻状态区。

点划状态色用于表达处理阶段，而不是单纯装饰：尚未确认的实时点划使用绿色，仅最新输入事件带轻微动态辉光；已确认并进入历史的点划改为冷灰白色并完全取消辉光，表现为已经固化的结果；候选边界使用低亮度灰绿色，确认边界使用灰白细线，不确定事件使用琥珀色，舍弃或错误事件使用橙红色，时间戳使用低亮度灰绿色。颜色之外还必须保留符号或文字状态，避免仅靠颜色传达含义。

页面显示的完整点划输入流与解码器内部的未决尾段分离：已稳定提交的事件从候选计算缓冲中释放，但继续保留在会话时间线和输入流中；解码器仅对尚未稳定分段的有限尾段保留候选路径。这样连续输入长度不受单字符位数限制，同时避免候选组合随整段会话无限增长。

### 4.4 `continuous-stream-segmenter`

该纯逻辑模块维护短期事件缓冲和候选拆分路径：

- 输入为按时间排序的点、划及相邻静息时长；
- 输出为已稳定提交文本、尚未确认尾段、当前分段状态和带原因的舍弃事件；
- 候选仅允许由标准摩斯表中的一至五位字母或数字组成；
- 候选得分以实际停顿接近字符内或字符间节奏的程度为主，不以词频替代生理时序证据；
- 候选数量设硬上限，防止长时间输入导致组合爆炸；
- 强制分隔时先提交所有候选一致的稳定前缀，再从最高时序置信候选中提交无歧义完整字符，最后舍弃不完整或仍有并列歧义的尾段；
- 每次提交、边界、舍弃和不确定动作均生成结构化事件，供页面日志和导出使用。

### 4.5 `continuous-code-session`

仅保存当前页面会话内的数据：校准参数、事件时间线、点划序列、解码结果、状态变化和必要的诊断摘要。默认不持久化到现有 IndexedDB。

用户主动导出时生成 JSON，包含参数和事件，不包含现有训练数据。刷新、退出页面或清空后会话结束。

## 5. 数据流

数据处理顺序固定为：

1. 串口单通道原始样本；
2. 当前静息基线中心化；
3. 轻量平滑和活动包络；
4. 启动伪迹、电极漂移和饱和门控；
5. 双阈值动作检测；
6. 动作持续时间和停顿时间测量；
7. 点划分类；
8. 自适应间隔分类、候选拆分和稳定前缀提交；
9. 页面显示和会话导出。

连续编码不得调用现有 `recognition-engine`、CNN、DTW、指令特征库或训练样本筛选逻辑。它只复用全局串口连接和静息基线读取能力。

## 6. 校准策略

用户每次进入页面或硬件重新连接后都必须完成本次会话校准：

1. 保持放松约 3 秒，估计静息噪声。
2. 舒适地短咬 3 至 5 次。
3. 舒适地长咬 3 至 5 次，避免数秒持续用力。
4. 系统检查动作是否高于噪声、两组时长是否可分、样本是否稳定。

正式解码中的阈值只允许缓慢适应静息噪声，不自动改写短咬/长咬分界，避免一次异常动作令整个会话漂移。重新连接、明显接触变化或连续异常后要求重新校准。

节奏参数不从肌电幅度推断。标准模式的普通字符边界初值为 700 毫秒、强制分隔初值为 2500 毫秒；慢速模式分别为 1200 毫秒和 4000 毫秒。自定义模式允许将普通字符边界设为 300 至 2500 毫秒、强制分隔设为 1500 至 10000 毫秒，并要求强制分隔至少为普通字符边界的 1.8 倍。普通字符间隔可根据本次会话已经确认的间隔以不超过每次 5% 的幅度缓慢更新，强制分隔阈值不自动漂移。调整节奏参数不会要求重新采集短咬、长咬校准，也不会改变动作分类结果。

## 7. 错误与安全处理

- 未连接硬件：禁止校准和开始，显示连接提示。
- 无静息基线或噪声过高：停止流程并要求调整电极。
- 短咬与长咬不可分：不给出伪精确阈值，要求重新校准。
- 启动伪迹或电极移动：暂停解码，不产生点划。
- 连续动作过长：标记为异常并暂停，避免把持续咬合解释为多个划。
- 无字符边界且存在多个同分拆分：保持尾段未确认，不以任意一个候选冒充确定结果。
- 强制分隔遇到非法尾段：只舍弃非法尾段并记录原始点划、时间和原因，保留此前稳定文本。
- 强制分隔遇到合法但仍并列歧义的尾段：不猜测字符，标记为不确定并舍弃该尾段。
- 串口中断：立即结束当前动作，不提交不完整字符；恢复后必须重新校准。
- 页面卸载：注销串口监听并释放运行忙碌标记。

页面需要明确提示用户只进行舒适、短时咬合；该功能是研发测试工具，不是医疗诊断或治疗功能。

## 8. 测试设计

### 8.1 纯逻辑测试

- 静息噪声不产生动作。
- 短动作产生点，长动作产生划。
- 接近边界的动作标记不确定而不是强行分类。
- 迟滞和去抖不会把一个动作拆成多个。
- 启动抛物线伪迹、电极漂移和饱和区间不产生符号。
- 字符内短停顿继续当前字符，字符间停顿生成候选边界并提交稳定前缀。
- 多字符连续输入能够逐步追加文本，而不是把全部点划压入单一字符。
- 多个候选共享前缀时只提交共同稳定前缀，分歧尾部保持未确认。
- 强制分隔提交静息前的稳定字符，并只舍弃最后一个非法、不完整或并列歧义尾段。
- 强制分隔后下一动作从新尾段开始，不污染此前事件缓冲。
- 连续输入超过单个字符最大五位时仍可继续显示和分段，不得因原有六位展示限制误判整段输入非法。
- 未决尾段超过候选计算上限时，只对未决尾段触发不确定或强制收口处理，不删除已提交文本和完整点划时间线。
- 下一次动作到来时能够从空闲状态正常恢复输入。
- 标准点划序列解码为预期字母和数字。
- 断开、暂停、重置不会提交残缺字符。

### 8.2 集成测试

- 新页面能够订阅和注销全局串口数据。
- 页面不写入现有指令、采集和识别历史表。
- 首页入口和受保护路由正常。
- 摩斯对照表完整包含 A 至 Z 和 0 至 9，且映射与解码器使用同一份常量。
- 会话 JSON 导出包含校准、事件和结果，且不包含训练数据库内容。
- 页面使用 JetBrains Mono 显示解码文本，最新字符后的动态光标连接真实运动的横向光纹；动画不会遮挡或替代可读文本。
- CH2 实时波形为页面主体，受试者能够直接观察咬合波形。
- 底部单行状态日志同时显示连续点划输入流、分段状态、舍弃状态和实时事件历史；符号、时间戳和间距采用紧凑尺寸，长点划流可横向滚动。
- 现有采集、识别、删除、导出测试全部继续通过。

## 9. 验收标准

1. 用户完成一次校准后，可连续输入点、划和字符边界，并在一次不中断会话中识别多个字符。
2. 熟练用户使用自然的短字符间隔连续输入时，不需要等待固定数秒；不熟练用户可用长静息强制分隔和恢复。
3. 强制分隔保留所有稳定字符，只舍弃最后一个非法、不完整或仍有歧义的尾段。
4. 页面实时显示 CH2 波形、可连续回看的点划输入流、流分段状态、紧凑事件历史和累计解码文本。
5. 页面提供与实际解码器完全一致的 A 至 Z、0 至 9 摩斯电码对照表。
6. 明显开场伪迹或接触移动不会生成字符。
7. 短咬、长咬不可可靠区分时系统拒绝开始，而不是给出错误结果。
8. 离开该页面后，现有指令训练数据、识别历史和模型状态完全不变。
9. TypeScript、完整测试和生产构建通过。

## 10. 后续但不属于本次实现

- 基于真实导出数据优化包络和阈值参数。
- 增加用户自定义点划短语或快捷指令映射。
- 比较标准摩斯码与更适合肌电疲劳特性的自定义编码表。
- 多电极/多通道到来后增加通道质量选择和融合，但保持解码状态机接口不变。
