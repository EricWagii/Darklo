# 连续肌电编码输入设计

## 1. 目标

新增一个独立的“连续肌电编码”页面，将耳周可稳定采集的咬合肌电动作解释为类似摩斯电码的点、划和停顿，并实时解码为字符或文本。

该功能用于验证耳周单通道肌电在连续时序输入上的可用性。它不替代现有的采集训练和离散指令识别，也不得改变现有训练样本、识别历史或质量评分数据。

## 2. 产品边界

第一版包含：

1. 连接状态和静息状态检查。
2. 本次会话的短咬、长咬和静息校准。
3. 连续肌电动作检测及点、划、字符间隔、词间隔识别。
4. 实时波形、当前编码、解码文本和不确定状态显示。
5. 暂停、继续、撤销上一字符、清空及导出本次会话。

第一版不包含：

1. 不训练 CNN、DTW 或新的语义分类模型。
2. 不写入指令、采集样本和现有识别历史数据库。
3. 不自动执行系统控制命令。
4. 不承诺默念语义识别，只验证有明显肌电活动的长短咬合编码。
5. 不在后台持续运行；仅在用户打开页面并明确开始后解码。

## 3. 页面和导航

新增受登录保护的路由 `/continuous-code`，首页提供明确入口“连续肌电编码”。页面沿用现有深色、克制的工作界面，不制作介绍型落地页。

页面从上到下包含：

1. 硬件与静息状态栏。
2. 校准区：依次采集静息、3 至 5 次短咬、3 至 5 次长咬。
3. 实时波形区：显示用于判定的单通道活动包络和动态阈值。
4. 实时解码区：显示当前点划序列、最近字符、累计文本和状态。
5. 操作区：开始/暂停、撤销、清空、导出和返回首页。

按钮使用现有图标库；数值状态使用固定尺寸，避免实时数据导致布局跳动。

## 4. 模块边界

### 4.1 `continuous-emg-calibration`

输入为静息和短咬、长咬的单通道样本，输出会话级参数：

- 静息中心和噪声尺度；
- 动作开始阈值与结束阈值；
- 最短有效动作时长；
- 短咬和长咬的自适应分界时长；
- 字符内、字符间和词间停顿阈值；
- 校准质量和失败原因。

短咬/长咬分界使用两组动作时长的稳健中位数中点，并要求两组之间存在最小分离度。分离不足时不允许开始正式解码。

### 4.2 `continuous-emg-detector`

将串口样本转为稳定的活动包络，采用双阈值迟滞、最短持续时间和去抖逻辑输出动作开始/结束事件。

检测器必须：

- 以当前静息噪声动态设阈值；
- 忽略过短尖峰；
- 将电极移动、饱和、长时间漂移和开场稳定过程标记为不可解码区间；
- 不因一次短暂低于阈值而把同一咬合拆成多次动作；
- 在信号恢复稳定前暂停产生点划符号。

### 4.3 `continuous-code-decoder`

纯状态机接收动作持续时间和动作之间的停顿时间：

- 短动作输出点；
- 长动作输出划；
- 字符内短停顿继续累积当前编码；
- 字符间停顿提交当前字符；
- 词间停顿提交字符并插入空格；
- 不确定动作不猜测，保留原始事件并提示重试。

编码表使用标准国际摩斯字母和数字映射。状态机为纯函数模块，不依赖 React、IndexedDB 或串口实现，以便独立测试。

### 4.4 `continuous-code-session`

仅保存当前页面会话内的数据：校准参数、事件时间线、点划序列、解码结果、状态变化和必要的诊断摘要。默认不持久化到现有 IndexedDB。

用户主动导出时生成 JSON，包含参数和事件，不包含现有训练数据。刷新、退出页面或清空后会话结束。

## 5. 数据流

数据处理顺序固定为：

1. 串口单通道原始样本；
2. 当前静息基线中心化；
3. 轻量平滑和活动包络；
4. 启动伪迹、电极漂移和饱和门控；
5. 双阈值动作检测；
6. 动作持续时间和停顿时间测量；
7. 点划分类；
8. 字符/词边界状态机；
9. 页面显示和会话导出。

连续编码不得调用现有 `recognition-engine`、CNN、DTW、指令特征库或训练样本筛选逻辑。它只复用全局串口连接和静息基线读取能力。

## 6. 校准策略

用户每次进入页面或硬件重新连接后都必须完成本次会话校准：

1. 保持放松约 3 秒，估计静息噪声。
2. 舒适地短咬 3 至 5 次。
3. 舒适地长咬 3 至 5 次，避免数秒持续用力。
4. 系统检查动作是否高于噪声、两组时长是否可分、样本是否稳定。

正式解码中的阈值只允许缓慢适应静息噪声，不自动改写短咬/长咬分界，避免一次异常动作令整个会话漂移。重新连接、明显接触变化或连续异常后要求重新校准。

## 7. 错误与安全处理

- 未连接硬件：禁止校准和开始，显示连接提示。
- 无静息基线或噪声过高：停止流程并要求调整电极。
- 短咬与长咬不可分：不给出伪精确阈值，要求重新校准。
- 启动伪迹或电极移动：暂停解码，不产生点划。
- 连续动作过长：标记为异常并暂停，避免把持续咬合解释为多个划。
- 串口中断：立即结束当前动作，不提交不完整字符；恢复后必须重新校准。
- 页面卸载：注销串口监听并释放运行忙碌标记。

页面需要明确提示用户只进行舒适、短时咬合；该功能是研发测试工具，不是医疗诊断或治疗功能。

## 8. 测试设计

### 8.1 纯逻辑测试

- 静息噪声不产生动作。
- 短动作产生点，长动作产生划。
- 接近边界的动作标记不确定而不是强行分类。
- 迟滞和去抖不会把一个动作拆成多个。
- 启动抛物线伪迹、电极漂移和饱和区间不产生符号。
- 字符内、字符间、词间停顿分别产生正确状态变化。
- 标准点划序列解码为预期字母和数字。
- 断开、暂停、重置不会提交残缺字符。

### 8.2 集成测试

- 新页面能够订阅和注销全局串口数据。
- 页面不写入现有指令、采集和识别历史表。
- 首页入口和受保护路由正常。
- 会话 JSON 导出包含校准、事件和结果，且不包含训练数据库内容。
- 现有采集、识别、删除、导出测试全部继续通过。

## 9. 验收标准

1. 用户完成一次校准后，可连续输入点、划、字符停顿和词停顿。
2. 页面实时显示波形、当前编码和解码文本。
3. 明显开场伪迹或接触移动不会生成字符。
4. 短咬、长咬不可可靠区分时系统拒绝开始，而不是给出错误结果。
5. 离开该页面后，现有指令训练数据、识别历史和模型状态完全不变。
6. TypeScript、完整测试和生产构建通过。

## 10. 后续但不属于本次实现

- 基于真实导出数据优化包络和阈值参数。
- 增加用户自定义点划短语或快捷指令映射。
- 比较标准摩斯码与更适合肌电疲劳特性的自定义编码表。
- 多电极/多通道到来后增加通道质量选择和融合，但保持解码状态机接口不变。
